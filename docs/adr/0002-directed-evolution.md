# Directed evolution, not random

The Instance must adapt — mutate, within the framework. Two models were considered.
Darwinian: agents freely rewrite governed files and problems are culled after the
fact — fast, and occasionally lethal (an agent silently rewriting its own
authority). Directed: an Instance uses a full Proposal when power grows and the
fast-track path when it does not; both put Checks and Founder Judgment *before*
the change reaches the conserved core. Lessons make acquired traits heritable
through `improve-a-process`. We chose directed. Accepted consequences: a slower
mutation rate, and the Founder as selection bottleneck until Judgment is
explicitly delegated. No mutation engines, variant machinery, or fitness scoring
are built — Git records every change, `proposals/` queues full mutations, the
fast-track ledger records light ones, and evaluation is the filter. The Seed
source uses maintainer PR review because it is a distributable pattern, not an
Instance.

The same choice creates a one-way ownership boundary. The Seed may publish a
better starting pattern, but it has no continuing Authority over an Instance.
An Instance reviews and adopts upstream changes through its own governance. An
Instance pattern moves back to the Seed only after it is generalized and
reviewed as Seed source. Shared learning travels; control does not.
